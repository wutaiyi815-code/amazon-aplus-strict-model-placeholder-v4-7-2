## 目标与适用场景

用于按 SKU 批量制作服装 Amazon A+ 内容，强调同一模特身份、产品细节、站点语言、当前 SKU 的参考图隔离，以及逐 SKU 同步生成与任务恢复。

支持模特场景、产品细节、网红自拍、后续替换用背景与明确要求的色块占位符。细节类模块执行直边排版限制；SKU 根目录中的人物图片不作为下游模特参考。

不适用于没有产品素材的自动商品设计，也不是上传 Amazon 商品页面的工具。不能仅凭文件名判断模特身份；缺少必要素材或 API 配置时需要补齐输入。

## 严格输入格式

```text
<ROOT>/
  模板.txt
  LOGO/                 可选；共享品牌 LOGO，文件名主体应匹配 Excel 品牌值
  <SKU>/                必须是 ROOT 的直接子文件夹
    1-产品属性表.xlsx
    素材/                 产品平铺、细节等素材
    上身/                 按视觉内容判断用途
    上身1/                可选素材目录
    AIGC/                 可选模特素材目录
    LOGO.png              可选，按模板允许情况使用
```

### 根目录和 SKU

- `<ROOT>` 必须存在；每个待处理 SKU 必须是其直接子文件夹。逐 SKU 命令中的 `--product` 只能填写一个精确文件夹名，不能填写路径、逗号分隔列表或整个根目录。
- 根级 `LOGO`、`输出结果*`、备份目录以及 `_aplus*`、`_influencer*` 工作目录不视为 SKU。
- 根目录必须提供 `模板.txt`。模板应明确模块数量、单模块尺寸和各 Section/Module 指令；模块编号应使用 `Section 1`、`Module 1` 或 `模块 1` 这类可解析格式。

### Excel 属性表

- 每个 SKU 必须有一个属性工作簿。优先读取精确文件名 `1-产品属性表.xlsx`；否则按文件名排序使用第一个非 `~$` 临时工作簿。
- 支持 `.xlsx`、`.xlsm`、`.xltx`、`.xltm`。推荐使用“第一列字段名、第二列字段值”的键值结构，并提供商品类型、颜色、版型、面料、卖点、品牌、市场/语言等可核实商品事实。
- `Section N Headline`、`Section N Copy` 等字段只属于同编号模块，不得跨 Section 复用；空白字段允许按模板和商品事实生成。
- 工作流开始时会删除键名为 `color_options` 的整行，并在修改工作簿前创建备份。

### 图片位置、格式和命名

- 核心语义标注和模块参考图支持 JPG、JPEG、PNG、WEBP；为避免不同辅助脚本的格式差异，公开用法统一推荐这四种格式。
- 可用素材放在 SKU 的 `素材`、`上身`、`上身1`、`AIGC` 等业务子目录。SKU 根层级中视觉确认含人物的图片会被硬排除，不能用作身份锚点、网红计划或下游模特参考。
- `弃用`、`过程文件`、`生成结果`、`输出结果`、`备份`、`备份目录`，以及 `_aplus*`、`_influencer*` 工作目录中的图片不得作为当前输入参考。
- 输入图片不要求固定数字文件名，但完整 SKU 相对路径必须唯一；相同文件名出现在不同子目录时仍按完整相对路径区分。
- 图片应清晰呈现需保留的模特身份、服装轮廓、颜色、印花、面料和前后面。不设统一输入像素门槛。

### 尺寸和参考图合同

- 模块数量和单模块尺寸以当前 `模板.txt` 为准。默认 API 示例使用 `21:9`、`2K`；网红自拍默认 `4:5`、`2K`，这些参数不能替代模板中的最终像素核验。
- 所有允许图片必须先汇总到当前 SKU 接触表，由用户选择的分析模型一次性进行语义标注；标注结果必须完整覆盖所有允许路径。
- 模特模块使用已确认的身份参考和少量商品准确性参考；细节、面料和工艺模块使用视觉确认的平铺或细节图。
- Section 2 必须包含简报中的精确 `model_identity_reference`，并在可用时增加另一张正面或三分之四人物参考。
- 单独的背面人物图不能作为唯一模特参考；必须配有正面或三分之四人物图，否则移除背面参考。
- Section 1 禁止使用背面模特参考。LOGO 只有在模板允许且图片被视觉标注为 `brand_logo` 时才能上传。
- 明确要求不使用参考图的模块必须生成空参考列表；RunningHub 端点因技术限制需要图片时，只能传脚本生成并记录的空白技术种子。
- GPT-RH 每次最多 10 张参考图；v4.7.2 的模块规划默认最多选择 6 张，再由生成端执行服务上限。
- 只有实际生成网红自拍时才需要背景图库；通过 `--background-root` 或 `APLUS_BACKGROUND_ROOT` 明确提供。

## 环境与依赖

本次本地验证使用 Python 3.12；建议使用该版本。依赖清单见 [requirements.txt](requirements.txt)，上游未记录锁定版本。Windows 为主要使用环境，其他系统尚未验证。远程 API 执行生图，本地不要求专用 GPU。

```powershell
python -m pip install -r requirements.txt
```

需要支持本地 Skill 和文件访问的 Codex 环境。生图可按 SKILL.md 选择内置 image_gen，或配置 ToAPIs / RunningHub；图像分析须指定服务实际支持的模型 ID。脚本中的模型名称、接口与可用性以所用服务为准，本发布未调用付费接口验证。

API 密钥从进程环境变量或交互输入提供：ToAPIs 使用 `TOAPIS_API_KEY` / `OPENAI_API_KEY`，RunningHub 使用 `RUNNINGHUB_API_KEY`。不要将真实密钥写入版本库或保存的命令。

## 安装与使用

将整个目录放入本机 Codex 的 `skills` 目录，保持文件夹名与 Skill 名称一致。向 Codex 提供产品根目录、分析模型和生图方式，并调用此 Skill。完整流程以 [SKILL.md](SKILL.md) 为准；不要跳过语义标注、人工视觉方向和生成前质量检查。

背景图库已改为可配置路径，以下两种用法均可：

```powershell
python "<SKILL_DIR>\influencer_scripts\prepare_selfie_batch.py" --root "<ROOT>" --background-root "<BACKGROUND_ROOT>"

$env:APLUS_BACKGROUND_ROOT = "<BACKGROUND_ROOT>"
python "<SKILL_DIR>\influencer_scripts\prepare_selfie_batch.py" --root "<ROOT>"
```

尖括号内容须替换为自己的目录。既未传参也未设置环境变量时，脚本会明确提示缺少背景路径。可选的历史优质案例校准目录由用户自行提供，不是运行依赖。

## 交付物

- 产品目录 `_aplus_creative_work/`：简报、模块提示词、参考图映射、生成状态、模块图片及拼接结果。
- 需要网红自拍时生成 `_influencer_selfie_work/`。
- 根目录 `输出结果/` 收集各 SKU 的长图；状态文件记录进度和恢复句柄。
- 模块 API 默认比例为 21:9、分辨率 2K；自拍默认 4:5、2K。最终模块尺寸与模板及脚本参数保持一致。

运行时产物可能包含用户素材路径、任务 ID 和结果链接，应保留在自己的业务目录，发布 Skill 时不要附带这些文件。
